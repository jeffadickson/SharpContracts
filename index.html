The real verifier checks assumptions AND NOT(claim). UNSAT means proved for the mathematical model; SAT means a counterexample exists; UNKNOWN means no conclusion. Use the .NET Z3 project for an actual solver result.


Milestone 3 — symbolic expressions


Build a typed predicate representing amount > minimum. Evaluate it, then inspect the SMT-LIB sent to an eventual theorem prover. The demo models the supported decimal comparison.







var amount = Expr.Param("amount", SymbolicType.Decimal);
var requirement = Expr.Gt(amount, Expr.Dec(0m));
var valid = ContractExprEvaluator.Check(requirement, environment);
var smt = SmtLibPrinter.Print(requirement);


The runtime evaluator operates on concrete values. The exporter describes a mathematical assertion over unbounded SMT Real values; C# decimal is finite and fixed precision, so these semantics are not yet equivalent for all arithmetic operations. There is no solver or proof execution.




Milestone 2 — typed contract boundary


Try a reusable typed contract set: the precondition rejects invalid input before work, and the postcondition checks the result after normal return. The JavaScript runner simulates the corresponding C# API.






var pre = new ContractSet<int>()
    .Add(new("REQ-POS", ContractKind.Precondition, "positive", n => n > 0));
var post = new ContractSet<(int Input, int Result)>()
    .Add(new("ENS-SQUARE", ContractKind.Postcondition, "square", x => x.Result == x.Input*x.Input));
int value = ContractBoundary.Invoke(3, n => n*n, pre, post);


Important: this is a strongly typed executable runtime model. It is not yet a serializable symbolic expression tree or a mathematical proof.


Automatic interface contracts
Milestones 1–2 include a C# DispatchProxy that checks parameter attributes before forwarding an interface call. Test that behavior in this JavaScript simulation.







public interface ITransferService
{
    void Send([ContractPositive("AUTO-001")] decimal amount,
              [ContractNotNull("AUTO-002")] string recipient);
}
var guarded = ContractProxy.Create<ITransferService>(service);
guarded.Send(0m, "Alice"); // AUTO-001 detected before service is called


Important: only calls through the proxy are guarded. Direct target calls and self-invocation are not intercepted.

Semantics and limitations
A failed precondition prevents entry. A failed postcondition detects a broken guarantee after mutation; this prototype does not roll back changes. C# `Old<T>` does not deep-copy referenced objects. Proof, automatic weaving, async contracts and Roslyn analyzers remain planned.
