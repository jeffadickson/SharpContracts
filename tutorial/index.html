1. What does a contract guarantee?

A precondition describes what a caller must establish. A postcondition describes what a successful method execution must establish. An invariant describes a property that must hold at agreed object boundaries.

Contract.Require(amount > 0,
    "PRE-001", "Amount positive");
Contract.Require(amount <= balance,
    "PRE-002", "Enough funds");
long remaining = balance - amount;
Contract.Ensure(remaining >= 0,
    "POST-001", "No overdraft");
Choose Run example.

Run-time checking examines one execution. Formal verification asks whether every permitted input can violate the claimed property.

2. How Z3 proves a contract

First check that the assumptions admit at least one input; otherwise an implication proof is vacuous. The verifier now rejects contradictory requirements such as x > 5 and x < 0. To establish assumptions ⇒ claim, a verifier asks Z3 whether assumptions ∧ ¬claim has a solution. UNSAT means the implication is valid in the encoded model; SAT provides a counterexample; UNKNOWN gives no proof.



This exercise uses a known mathematical-integer example. The repository's real Z3 solver is in SharpContracts.Solver.


3. The overflow trap
Mathematical integers are unlimited. C# int and long are not. In unchecked contexts, integer addition wraps; in checked contexts it throws when it overflows.




The current compiler-bound verifier models selected unchecked expressions. It rejects checked arithmetic rather than claiming an unsound proof.


4. The C# type system matters
Roslyn resolves promotions and overloaded operators. byte + byte actually produces an int, while an overloaded custom type can perform arbitrary code.


Custom numeric types must be proven by analyzing their operator implementation or using a clearly identified trusted specification. An operator named + is not automatically ordinary addition.


5. Run the real implementation

The verification test suite now includes C# versus Z3 differential cases at integer boundaries and all 65,536 byte-addition input pairs. The following commands execute the repository's C# runtime and tests using .NET 8 or newer with suitable native Z3 dependencies.
git clone https://github.com/jeffadickson/SharpContracts.git
cd SharpContracts
dotnet restore SharpContracts.Verification.Tests/SharpContracts.Verification.Tests.csproj
dotnet test SharpContracts.Verification.Tests/SharpContracts.Verification.Tests.csproj
dotnet test SharpContracts.Solver.Tests/SharpContracts.Solver.Tests.csproj
dotnet run --project SharpContracts.Demo

dotnet run --project SharpContracts.Cli -- examples/VerifiedByteAddition.cs Check
dotnet run --project SharpContracts.Cli -- examples/OverflowCounterexample.cs Check


The CLI uses exit code 0 for proved, 1 for counterexample/unknown, and 2 for unsupported/invalid inputs. The overflow example is expected to exit 1. Inspect BoundNumericVerifier.Verify(source, methodName) in SharpContracts.Verification/BoundNumericVerifier.cs. The binder uses Roslyn IOperation to determine numeric types and constructs Z3 bit-vectors. Unsupported features are rejected.


Where the implementation stands
Implemented in source: runtime checks, typed symbolic expressions, Z3 implication queries, restricted source verification, and an experimental Roslyn-bound numeric verifier. Not established: a passing .NET CI build, complete numeric conversion rules, general control-flow support, verification of user-defined operators, or soundness for all C# code.
